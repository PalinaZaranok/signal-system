# ТЗ — Система сбора и визуализации сигналов

## 1. Ключевые добавленные параметры

| Параметр | Значение по умолчанию |
|---|---|
| Частота дискретизации АЦП `Fs` | 80 000 Гц (настраивается) |
| Разрешение АЦП | 12 бит (0…4095), `uint16` в пакете |
| Число каналов | 1 |
| Диапазон входа | 0…3.3 В (Nucleo-F103RB ADC, Vref=VDD) |
| Размер пакета | 128 отсчётов (настраивается 16…255) |
| Скорость USART | 2 000 000 бод (8N1) |
| Пропускная способность | 262 байта/пакет × 625 пак/с ≈ 164 кБ/с (1.64 Мбод) |
| Запас по линии | ≈16 % |
| Размер окна FFT | 2048 (настраивается 256…16384) |
| Оконная функция | Hann / Hamming / Blackman / Rect |
| Частота обновления GUI | ~30 Гц |
| Окно графика времени | 20 мс (настраивается) |
| Кольцевой буфер | 1 000 000 отсчётов |
| Протокол | бинарный: sync + id + N + payload + CRC16-CCITT |

## 2. Архитектура ПО (ПК)
- `QThread` (Mock / Serial) → `bytes` → `PacketParser` → `RingBuffer` → 
  - временной график (последние `Fs × window` отсчётов),
  - спектр (FFT последних N_fft отсчётов с окном).
- GUI обновляется `QTimer` (~30 Гц), а не на каждый пакет — интерфейс не блокируется.
- Mock-режим генерирует **реальные байтовые пакеты** того же протокола и эмулирует тайминг — проверяет парсер, буфер и стабильность GUI.

## 3. Критерии готовности
1. Запуск в Mock без «железа»: видны 3 гармоники на спектре (1, 3.5, 7.2 кГц при Fs=80 кГц), GUI стабилен при Fs до 200 кГц.
2. По USART реальное устройство выдаёт поток, парсер считает потери/CRC-ошибки.
3. При отключении платы во время работы GUI корректно сообщает об ошибке.
